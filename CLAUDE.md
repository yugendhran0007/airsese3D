# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm run dev` — Vite dev server (default port 5173; picks the next free port if taken)
- `npm run build` — `tsc --noEmit && vite build`; the build is typecheck-gated and fails on any type error
- `npm run typecheck` — `tsc --noEmit`
- `npm run preview` — serve the production build

There is no lint script, no ESLint config, and no test runner — verification is typecheck + driving the app. Package manager is npm (`package-lock.json`). `vite.config.ts` is minimal (react + tailwind plugins, raised `chunkSizeWarningLimit`); there is no `.env` and no path aliases.

**Headless verification** (no GPU needed): `node scripts/verify.mjs <url> <shot.png> [waitMs]` launches system Chrome via puppeteer-core, screenshots the app, and dumps live engine state through the dev-only globals `window.__engine`, `window.__ui`, `window.__char`, `window.__scenario`, `window.__scene` (the three.js scene graph). `node scripts/shot.mjs <out.png> '<json>'` screenshots a given view: `{"cam":[x,y,z]}` (orbit camera position), `{"mode":"follow","tele":[x,z,heading]}` (teleport the player, chase cam), `{"render":"stylized"}` — it hardcodes `localhost:5173/?nofx` and also needs `window.__camera`. Other `scripts/*.mjs` (`diag`, `closeup`, `interact*`, `finalshots`) follow the same pattern but hardcode `localhost:5183` (also `verify.mjs`'s default when no URL is given) — edit the port to match your dev server. `scripts/_*_tmp.mjs` are throw-away experiments, not tooling. All scripts launch `/usr/bin/google-chrome` with SwiftShader. Append `?nofx` to the URL when running under SwiftShader for usable FPS; realistic mode needs ~60–90 s to mount headlessly, so wait on `window.__scene` rather than a fixed delay. The dev globals are installed from `simStore.ts` (`__engine`, `__ui`), `characterStore.ts` (`__char`), `scenarioPlayer.ts` (`__scenario`) and `Scene.tsx` (`__scene`, `__camera`, `__gl` — the WebGLRenderer, handy for `__gl.info.programs`). For load-time profiling use a **headed** Chrome on the real GPU (`headless: false`, `DISPLAY=:0`, `--ignore-gpu-blocklist`): SwiftShader inflates shader-compile and texture-upload costs ~10× and headless Chrome cannot reach the AMD GPU here. Chrome's on-disk shader cache makes repeat loads much faster than a fresh puppeteer profile shows — measure both.

`node scripts/optimize-avatars.mjs` regenerates the human GLBs in `public/models/people/` from the untouched originals in `models-original/` (not served): strips the VALID avatars' 96 facial morph targets, downsizes textures to 1024² WebP and re-meshopts them (1.8 MB → 0.65 MB each), and reduces `Soldier.glb` to bone nodes + clips (2.1 MB → 0.4 MB). `OUT_DIR=public/models/people-lite MAX_TEX=512 SIMPLIFY=0.4 node scripts/optimize-avatars.mjs` builds the **lite tier** (512² textures, 40 % triangles, ~0.33 MB each) used by Fast/Balanced; `tierUrl()` in `realisticPeople.ts` picks the folder from `uiStore.quality` (the player avatar always uses the full asset). Re-run both after replacing any source model.

## What this app is

AirSense (`md` at the repo root is the full 65-section spec; `itmd` is a condensed restatement; README.md has the feature tour): a frontend-only, real-time 3D visualization of indoor air quality in a Chennai IT office. Live outdoor weather/AQI from the **keyless** Open-Meteo APIs feeds context into a browser-side physics simulation (CO₂/temperature/humidity per zone), rendered as a walkable React Three Fiber office. There is no backend, no API keys, no `.env`.

## Architecture

### The signature pattern: per-frame data never enters React

- `src/simulation/engine.ts` exports a singleton `engine` (class `SimulationEngine`, plain TS, no framework). It ticks on a 10 Hz `setInterval`, integrating physics in Euler substeps at 60 sim-seconds per real second × speed.
- R3F components read `engine.snapshot` / `engine.params` **directly inside `useFrame`** at 60 fps with zero re-renders.
- The DOM gets throttled 4 Hz snapshots via zustand (`connectEngine()` in `src/state/simStore.ts` wires engine listeners into the store).
- The player character's per-frame position lives in the mutable `characterTransient` object (`src/state/characterStore.ts`), not React state; the store itself only holds coarse zone crossings.
- The scenario player (`src/simulation/scenarioPlayer.ts`) and ramp mode (`src/simulation/rampMode.ts`) are module-level state stepped from `useFrame`.

When adding features, follow this split — do not lift per-frame data into zustand.

### Data flow

```
OutdoorProvider (Open-Meteo | Dummy | Sensor-stub)
  → weatherPoller → weatherStore → engine.setOutdoor()
engine (10 Hz physics, 4 zones + inter-zone mixing, ring-buffer history)
  → 4 Hz snapshots → simStore → DOM panels/charts (Recharts)
  → read directly in useFrame → 3D scene
```

- **Engine is the source of truth for `params`**: every `simStore` mutator writes to the engine first, then mirrors `engine.params` back into the store.
- Four zustand v5 stores: `simStore` (params/thresholds/snapshot/alerts), `uiStore` (mode, cameraMode, `renderMode: 'realistic'|'stylized'`, panel flags, selections), `weatherStore` (outdoor reading + staleness), `characterStore` (zone only).
- Physics lives in pure functions in `src/simulation/physics.ts` (all rates per-hour); zones are a 2×2 grid defined in `src/simulation/zones.ts`; status/alerts/recommendations in `statusEngine.ts` / `alerts.ts` (60 sim-second hysteresis to prevent flapping) / `recommendations.ts`.
- The provider seam (`src/providers/OutdoorProvider.ts`) is sacred: future real sensors (ESP32, spec §39–42) must arrive as one new provider implementation with zero frontend changes. Weather polling handles backoff, keeps the last reading, and marks it STALE after 20 min — never silently passes stale data off as live.

### 3D scene

- `src/scene/Scene.tsx` is the `<Canvas>`; `OfficeWorld` inside it is the branch point for the **Realistic / Stylized render-mode toggle** (`uiStore.renderMode`, default realistic, "Real/Styled" button in `TopBar`).
- Realistic mode is modelled on a modern IT-office fit-out (white bench desks with grey privacy screens and beige pedestals, black mesh task chairs, grey carpet, suspended tile ceiling with linear LED bars/downlights/pendants, 4-way AC cassettes, fire-exit signs, white columns). It is almost entirely procedural: `RealisticFurniture.tsx` (desks, chairs, meeting tables, `Cafeteria` with round tables/teal lounge chairs/coffee counter, white lockers) and `RealisticCeiling.tsx` build instanced parts via the generic `Instanced`/`Part` helper. The only GLTFs left are KayKit planters/books (`GltfInstances`) and the humans.
- **Do not try to merge a VALID avatar's submeshes.** Each avatar is split into ~5 skinned meshes (body, `h_L_eye`, `h_L_gland`, `h_R_eye`, `h_TeethDown`) that share material, bones, node transform and bindMatrix — but each carries its **own `boneInverses`** (a different bind space) and meshopt-quantized `Int16` positions, so `mergeGeometries` + a single `bind()` shreds them into stretched shards. This was tried and reverted; the ~268 skinned draws for ~56 characters are the cost of these assets.
- Seated-avatar performance rules (`RealisticCrowd.tsx`): skinned meshes are **frustum-culled** using `SkinnedMesh.computeBoundingSphere()` taken after posing (padded ×1.25) — do not set `frustumCulled = false` on the seated crowd again; they **cast no shadows** outside ultra (the shadow pass would re-skin them); beyond `ANIM_LOD_DIST` (22 m) their micro-animation is skipped. Desk/meeting sitters look down at their laptop (`applyPose`) and type via alternating `WorldXRotator` forearm taps with pauses.
- Humans: VALID-library business avatars (`public/models/people/*.glb`, CC-BY 4.0, meshopt-compressed) for the seated crowd (`RealisticCrowd`, first `REALISTIC_PER_ZONE` = 24 per zone (`RealisticCrowd.tsx`); `Crowd` fills overflow with `skipFirst`), the player (`RealisticBody`) and six walkers (`WanderingNpcs`). Animation comes from the three.js Soldier GLB's Mixamo clips via `retargetMixamoClips` in `realisticPeople.ts` — a **world-space** retarget (sample the clip on a Soldier clone, apply each bone's world-rotation delta from its T-pose to the VALID bone's T-pose, convert back to local). Do not go back to copying local quaternion tracks: the two rigs' bind poses differ (Soldier's Hips sits under a −90° X node; VALID bakes axis conversion into bone rests) and that lays avatars flat. Likewise static poses use `rotateBoneWorld`/`WorldXRotator` (world axes), never `bone.rotateX`. VALID rigs carry their cm→m scale on the Hips bone, so scale tracks are dropped; avatar height is measured from the Head bone, never `Box3.setFromObject`. Rest-relative retargeting keeps the rig's own +Z facing, so there are no `rotation-y={Math.PI}` wrappers on VALID avatars.
- Walkers follow waypoint routes in `WanderingNpcs.tsx` with Idle pauses (`pause`/`face`): side corridors at x = ±(W/2 − 1.6), the z = 0.5 cross aisle, the x = 0 spine, room doors, and the cafeteria walkway. Routes are hand-built from `layout.areas`; if you change the layout, re-check them against `layout.obstacles` (a throw-away script that samples each segment against the obstacle circles is the quickest way).
- Every GLTF component sits in `<Suspense>` with its procedural equivalent as fallback (`RealisticFurniture` → `Furniture`, `CustomOffice` → `OfficeShell`), so missing assets degrade instead of breaking.
- Light rig by tier (`Lighting.tsx`): Fast = ambient + hemisphere + key (no shadows); Balanced adds the cool fill and shadows; only 8K/ultra has the four point lights (per-fragment cost on every material) — the PMREM environment (`environmentIntensity` 0.8 outside ultra) carries the ceiling glow instead. Tone mapping is **AgX** at exposure 1.45 (`Scene.tsx`); `index.html` preloads the first GLBs.
- Realistic-mode lighting is image-based: `RealisticEnvironment.tsx` builds its own HDR office light rig (mullioned daylight window wall, rows of individual LED tubes, warm side spots, theme-tinted feature wall, brighter floor aisle) and bakes it through PMREM into `scene.environment` — no HDR asset to load. **Resolution is tiered** via `fromScene(..., { size })`: 128² Fast, 256² Balanced, **1024² ultra**, with a smaller blur sigma at ultra so window/LED shapes survive; the cube camera sits at eye height (y=1.6). The rig is modelled with real gaps (mullions, dark runs between tubes) — a flat emissive panel bakes to a featureless smear at any resolution. Emissive values ≫1 there are intentional.
- **Employee mode** (`uiStore.employeeMode`, "Anon/Employees" button in `TopBar`): name tags are hidden by default and shown for everyone only in employee mode (a clicked person's tag always shows). Every occupant has a floor **safety ring** coloured by `personStatus(seed, zoneStatus)` in `effects.ts` (green safe / yellow medium / red danger); `RealisticCrowd` draws all rings in one `SafetyRings` instanced mesh, `Crowd` uses the same helper for its instanced ring. Keep rings + tag dots + inspector using that one function.
- `WallTvs.tsx` plays **only** the Finstein brand animation (user's explicit choice — no slides, ticker or data): stepped-F mark builds, wordmark wipes, tagline fades, light sweep + breathe, clean 8 s loop, over a drifting-network background. Painted into a shared `CanvasTexture` from `useFrame`; the deck is authored in 1024×576 units and scaled via `ctx.setTransform` per quality tier.
- **Data Viz** (`src/ui/dataviz/DataVizOverlay.tsx`, `uiStore.dataVizOpen`, "Data Viz" navbar button): a people-unit view — one glyph (Human mode) or LED seat-cell (Digital mode) per occupant in the 2×2 zone grid, coloured by `personStatus` with a posture/icon + label, hero counts, threshold "breath meters" and a table view. It reads the 4 Hz store snapshot only. Per-seat readouts show the **zone** reading — there are no per-seat sensors, never invent per-person values.
- **Quality tiers** (`uiStore.quality`: `'fast' | 'balanced' | 'ultra'`, persisted in `localStorage` `airsense.quality`; Fast/Bal/8K segmented control in `TopBar`; `ultraQuality` is the derived boolean). **Fast** is the production-lightweight tier: DPR ≤1, no key-light shadows, no postprocessing, `realisticPerZone()` = 4 skinned avatars per zone (Balanced 12, Ultra 24; the rest are the instanced crowd), TV at 1024² @12 fps, screen textures @3 fps; `PerformanceMonitor.onFallback` auto-drops Balanced → Fast, and on first visit `recommendQuality()` (`src/utils/hardware.ts`: cores/RAM/GPU renderer string) picks the starting tier so integrated-GPU laptops begin in Fast. The Canvas sets `frameloop='never'` while the tab is hidden; `SceneErrorBoundary` (App.tsx) replaces a crashed canvas with a GPU/acceleration hint. **8K/ultra** pins canvas DPR at the device max (≤2), renders the TV deck at native 4K (3840×2160) and monitors at 2×, 4096² shadow maps, max anisotropy. The TV deck is authored in 1024×576 units and scaled via `ctx.setTransform`, so never hardcode pixel sizes in `WallTvs.tsx` painters.
- **Closing UI (🗙)**: every card/drawer/overlay closes with the 🗙 symbol (`CloseX` in `src/ui/shell/CloseX.tsx`). Dashboard cards are wrapped in `Closable` (hidden state in `uiStore.hiddenCards`); self-positioned panels (navbar, controls, alerts, HUD, scenarios, mini-map) use `Closable bare` + their own inline `CloseX`. The `RestorePill` (bottom-right) re-opens closed cards. Keep new panels on this system and use the 🗙 glyph, not lucide `X`.
- **Presentation** (`scenarioPlayer.ts` + `CameraRig.tsx` + `PresentationOverlay.tsx`): scenes carry `camera.position` → `camera.to` dolly keyframes eased over `presentationProgress()`; keep low keyframes inside the walls (|x|<14, |z|<9, y<3.4 for the default 30×20×3.6 m room) or high above the roof. ←/→/Space step scenes via `stepPresentation`.
- Shell extras in `src/ui/shell/`: `LoadingScreen` (drei `useProgress`), `Onboarding` (first-visit tour, `localStorage` key `airsense.tour.v1`), `Shortcuts` (global keys + `?` sheet — avoid WASD/QE/arrows, which belong to the character controller), `MiniMap` (click to walk).
- `ShadowScheduler` (`Scene.tsx`) sets `gl.shadowMap.autoUpdate = false` and refreshes the map every 4th frame (2nd in ultra), plus continuously for an 8 s warm-up while GLTFs stream in and whenever room/quality/renderMode changes — the office is static geometry, so re-rendering ~140 casters every frame was waste. `RealisticCrowd` and `NameTags` each run **one** `useFrame` that drives every person through a registered-tick array instead of one R3F subscriber per person (~110 → 2), and `NameTags` returns `null` entirely unless employee mode is on or someone is selected.
- `Scene.tsx` uses drei's `PerformanceMonitor` to step the canvas DPR between 0.8 and 2 from measured frame rate (`powerPreference: 'high-performance'`); `Effects.tsx` additionally drops postprocessing on sustained <28 FPS.
- Assets present in `public/models/`: `Soldier.glb` (animation source), `furniture/` (KayKit Furniture Bits GLTF+bin, shared `furniturebits_texture.png`, plus a Poly Haven-style `wooden_table_02/` with its own `textures/`), `people/` (ten VALID `*_Busi.glb` avatars: Asian/MENA × F/M). Loose reference images/screenshots at the repo root are design references, not app assets.
- `CustomOffice.tsx` is a dormant Sketchfab drop-in: it HEAD-probes `public/models/office/scene.gltf` (+3 variants) and, if the user has placed a model there, replaces the procedural `OfficeShell` auto-fitted to room dimensions. The directory does not exist by default.
- Room dimensions live in `DEFAULT_PARAMS.room` (`src/config/constants.ts`), default **30 × 20 × 3.6 m** (2,160 m³) — 3.6 m floor-to-slab so the suspended ceiling, LED bars and AC cassettes have headroom above standing people. Height is user-adjustable 2–12 m; every shell/ceiling/HVAC/pendant position is expressed as a fraction of `room.height`, so nothing needs touching when it changes. `NumberInput` takes a `step` (0.1 for height) and only rounds the display when the step is whole.
- The office layout is fully derived from room dimensions in `src/scene/office/officeLayout.ts`: desk pods (slid toward the room centre until their footprint clears every area), seats tagged `kind: 'desk' | 'meeting' | 'cafe'` (`facing(angle)` = (sin, cos); chairs sit 0.42 m and sitters 0.28 m behind the seat point — never assume angle is 0/π), standing spots, `areas` (glass `conference` hall on the back wall with an off-centre door, two glass `meeting` rooms in the back corners with doors toward the interior, open `cafeteria` front-right), `cafeTables`, `columns`, and circle obstacles for the character controller. Per-zone seat order is one desk pod → meeting/café seats → remaining desks so moderate occupancy already shows meetings and breaks. `ConferenceRoom.tsx` renders every area (glass rooms + cafeteria rug/labels); `tableSize()` is the single source for meeting-table dimensions. Its glass is `meshPhysicalMaterial` with `ior` 1.52 + clearcoat + `envMapIntensity` 2.2 — the realism comes from reflecting the HDR office rig, **never** from `transmission`, which forces an extra full scene render pass per pane. `HvacUnits.tsx` exports `ventPositions()` which the particle system imports for emitter placement.
- `AirflowParticles.tsx`: all particle motion is in a custom GLSL vertex shader; the CPU only damps uniforms toward engine params.
- `Crowd.tsx` (largest file) renders up to `MAX_PEOPLE × 4` = 400 people via 14 parallel `InstancedMesh`es written from a single `useFrame` with shared scratch objects.
- Character control (`useCharacterController.ts`): WASD/arrows (camera-relative) **and** click-to-walk (`FloorClickTarget` in Scene.tsx) — both must be preserved. A movement key in orbit mode auto-switches the camera to follow; ESC returns. Follow cam is a spherical orbit around the player stored in `characterTransient` (`camDist`/`camYaw`/`camPitch`): **Q zooms in, Shift zooms out**, mouse drag on the canvas orbits (front/back/side views), wheel zooms — listeners are attached in `CameraRig.tsx`. There is no Q/E turning any more.
- `TopBar` is collapsed by default: the AIRSENSE brand is a menu button; collapsed it shows only the clock, play/pause and 🗙.
- Meeting rooms (`ConferenceRoom.tsx`): `RoomScreen` gives each room display content — `meeting-west` shows `public/textures/ai-head.jpg` (the "AI session"), `meeting-east` the code screen, the conference hall the AI training dashboard, all from the shared `useScreenTextures()` bundle (module-level singleton; any consumer may tick the repaint). In realistic mode `Presenter.tsx` stands a gesturing avatar beside the west room's display (procedural world-axis bone rotation via `WorldXRotator(bone, axis)`).
- Desk-end planters (white box + instanced icosahedron foliage) are procedural in `RealisticFurniture.tsx` `decor` — one per pod, alternating sides.
- Realistic-mode decor layers (all procedural, derived from room dimensions): `InteriorDecor.tsx` (feature walls, oak slats, cafeteria timber raft, aisle runners, wall art), `WallTvs.tsx` and `screenContent.ts` (TV/monitor/laptop content painted into shared `CanvasTexture`s from `useFrame` — no React state), and `NameTags.tsx` (one cached canvas sprite per occupant). Interior colour presets live in `src/config/officeThemes.ts` (`OfficeThemeId`, selected via `uiStore.officeTheme`); desks/chairs/ceiling stay the white baseline, themes only recolour walls/feature panels/carpet. Five presets, including **Noir Ember** — the genuinely dark one (near-black walls, deep teal, ember orange). Each theme also carries `frame`/`mount` colours for the poster frames.
- **Wall posters** (`InteriorDecor.tsx`, `POSTERS`): real image textures cropped from the user's source images into `public/textures/posters/` (`imagine`, `failure`, `bharathi`). Every frame is sized from its poster's own aspect ratio — never stretch artwork into a shared frame size. The print material feeds its own texture into `emissiveMap` at ~0.35 so colours stay vivid under the dark themes instead of going muddy grey.
- `src/config/employees.ts` is a deterministic **mock** employee directory (`employeeFor(zone, index)`, badge ids like `FIN-A-03`, `mock: true`) shared by `NameTags`, `PersonInspector` and the crowd so identity is stable across frames and click-to-inspect. Slot order must stay in sync with `RealisticCrowd`/`Crowd` (seats, then standing spots). Never wire real HR data through it.
- `Effects.tsx` auto-disables postprocessing after ~5 s below 28 FPS; `?nofx` in the URL forces it off.
- **Load-time rules** (`src/scene/useAsyncCompile.tsx`): three.js compiles a program on the first draw that uses it and the GPU process does that serially, so drawing the whole office at once froze the page for seconds. Every GLTF-backed subtree is wrapped in `<Compiled>` just inside its `<Suspense>` (and the whole initial `OfficeWorld` once): it mounts hidden and reveals two shader-variant groups per frame, compiling each just before it shows. Keep new heavy subtrees inside a `Compiled`, and never let a `useGLTF` component render without a `Suspense` below the Canvas-level one (that single missing boundary on `RealisticBody` used to blank the entire scene until every model had loaded). `prepareAvatarSource()` strips leftover morph targets at runtime and `getRetargetedClips()` caches the Soldier→VALID retarget per model; `retargetMixamoClips` matches joints by name because the shipped Soldier has no skin. `gl.debug.checkShaderErrors` is off in production.

## Domain invariants (non-negotiable, from the spec)

1. **Never dramatize O₂.** `o2FromCo2()` derives it from CO₂ displacement (~20.7–20.95%); it is always badged SIMULATED (StatCard's `simulated` prop defaults to true).
2. **Not medical advice.** `effects.ts` / `HumanInsightPanel` / `PersonInspector` are illustrative population-level visualizations with permanent disclaimers; recommendations are environmental actions only.
3. **Occupancy alone ≠ danger** — CO₂ is generation vs. air-changes; the correlation view exists to make this point.
4. **Stale weather is labeled STALE**, never passed off as live.
5. **Occupants stay anonymous** (`Person A-03` IDs, no personal data).
6. Outdoor CO₂ is a constant 420 ppm (Open-Meteo has no CO₂ endpoint), tagged `E` (estimate).

Doc comments cite spec sections (e.g. `(spec §37)`) — continue that convention.

## Conventions

- TypeScript strict + `noUnusedLocals`/`noUnusedParameters`; `verbatimModuleSyntax` is on, so type-only imports must use `import type`.
- No path aliases — all imports are relative. Don't introduce `@/` without adding both tsconfig `paths` and Vite `resolve.alias`.
- Tailwind v4, CSS-first: the entire design system is the `@theme` block in `src/styles/index.css` (no tailwind.config.js). Theme tokens are used as utilities (`bg-panel`, `text-ink`, `text-ok`, `border-line`, …); `.glass` is the shared frosted panel, `.num` the monospace numeric style.
- `STATUS_COLORS`/`ACCENT_COLOR` in `src/config/constants.ts` intentionally duplicate the CSS theme vars so the palette works in both DOM and `THREE.Color` — keep them in sync.
- Determinism: use `seededRandom` from `src/utils/math.ts` for anything persistent across frames (crowd appearance, affected-person selection, textures) — never bare `Math.random()`.
